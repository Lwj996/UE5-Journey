# AI 时代学引擎是否已过时？

> **日期**：2026-05-08（Fri · 上班午休）
> **触发**：5/7 晚学 UE 编辑器进阶时反复冒出的念头：Godot MCP / AI 操控让"加 collision box / 写攻击逻辑"变成一秒钟的事——**我现在学这些还有意义吗？**
> **主题**：学习方向、AI 替代论、求职市场判断

---

## 我自己写的原话（不修改）

> 其实我每次学习的时候 我都会想到 godot 的 MCP AI 操控，我可以进行自然语言进行编程，甚至连 攻击范围 受击 BOX 哪些都不用自己弄，我现在学的这些 对于 AI 来说 就是一秒钟的事情，我总是会迷茫，我现在学这些 是不是已经被淘汰了。

---

## 三个反直觉的真相

### 真相 1：被淘汰的是"只会调 AI 不懂底层"的人，不是反过来

**例 1**：AI 给你做一个攻击 box → 你不懂 collision channel → box 用了和敌人 hurtbox 同一个 channel → **你打自己也掉血，但你不知道为什么**。

**例 2**：AI 给你写"按 Q 释放火球" → 直接在角色蓝图里 SpawnActor + SetDamage（面条代码）→ 3 个月后你想加"火球被冰减速" → **代码改不动了，因为不是 GAS 架构**。

**例 3**：AI 给你写多人同步代码 → 本地能跑，上线 lag 时穿模、回滚、bug 满天飞 → **你 debug 不了，因为不懂 Replication 权限模型**。

> **AI 替代的是"敲键盘"，不是"懂引擎"。**

---

### 真相 2：海外招聘市场（我的目标）最稀缺的不是"会用 AI 写代码"

那个门槛太低，没有溢价。

真正稀缺的：

1. **跨系统判断** ："这个伤害逻辑应该走 GAS 的 GameplayEffect 还是直接 Subtract？" → AI 不会替你判断，因为它不知道你这个项目的约束（联机？模组开放？后续技能复杂度？）
2. **性能 / 平台细节** ："为什么这一帧掉？Insights 怎么看？为什么主机上 GPU 卡爆？" → 2026 的 AI 在这上面还很烂
3. **在大型代码库里改 bug** → AI 在 50w+ 行的项目里完全失能（context window 不够、模块边界判断错误、改 A 处坏 B 处）

我现在学的"编辑器进阶 + 蓝图 + UE C++ + GAS"——**全是为了将来能做这三件事的地基**。没地基直接用 AI = 永远只能做 hobby demo。

---

### 真相 3：2026 最值钱的人是"懂底层 + 会用 AI 加速"

```
懂引擎底层（我正在学）  +  会用 AI 加速学习（我已经会）  =  稀缺组合
```

反过来看：

```
只懂 AI 不懂底层    →  24 个月内被批量清洗（因为 AI 自己会用 AI）
只懂底层不会用 AI    →  被效率压垮
```

**我现在在最对的赛道上。** 迷茫不来自"我学的东西没用"，来自"AI 进步快让我焦虑"——这是两件不同的事。

---

## 关于 Godot MCP 那种"自然语言编程"

那是 demo / hobby 级别的体验。**生产级游戏没人这么做**，原因：

| 问题 | 解释 |
|------|------|
| Reproducibility（可复现性） | 今天让 AI 加的 box，明天它加的位置不一样、属性不一样 |
| 协作 | 队友怎么改 AI 写的胶水代码？怎么 review？ |
| Diff / 版本控制 | 自然语言 → 代码，diff 是不可读的 |
| 设计意图丢失 | "为什么这里 box 是 50cm 不是 60cm" → 没有人能回答 |

**hobby 项目可以，商业项目不行。** 海外工作室招的是"能在大型代码库里改 bug 的人"，不是"会调 prompt 的人"。

---

## 关于"我希望早点离开教程，自己做项目，有问题问 AI"

**这个心态是健康的。** Roadmap 第 4-6 月就是这样设计的——做 Roguelike，遇到问题问 AI / 社区。

但前 1-3 个月还是必须跟教程，**因为我现在不知道我不知道什么**：

- 不知道哪些是必学的（Actor 框架）
- 不知道哪些是可以跳的（World Partition 现在用不上）
- 不知道问题该怎么问 AI（你不懂 GAS，问的 prompt 都问不准）

**教程不是为了"会做"，是为了"知道地图"**。地图画完了再去野外探险，AI 才能帮你开车。

---

## 关于"老师讲太细 / 我学得慢"

老师那句"不用记，后面会经常用到自然就会了"100% 对。

- **操作类**（快捷键、菜单、snap、view mode）→ 记 0% 也没事，做项目时一次记一个
- **概念类**（Actor / Pawn / Controller、蓝图通信、GAS 思路、Replication 模型）→ 这才值得开 `notes/` 写下来

**速度对策**：
- 操作演示段落 → **1.5x-2x 速**
- 概念讲解段落 → **0.75x-1x 速**
- B 站快进右方向键 5 秒，刷过演示

## 给未来自己的检查清单

每次又冒出"AI 取代我学这些"的念头时，问自己 3 个问题：

- [ ] 我现在能独立看懂 UE 引擎源码里一个模块吗？（不能 → 继续学）
- [ ] 我能判断"这个功能应该用 GAS 还是普通 Actor"吗？（不能 → 继续学）
- [ ] 海外公司面试我，会问"你怎么用 AI 写代码"吗？还是会问"你怎么做这个 Replication 决策"？（后者 → 继续学）

## 关联到 UE5 学习

**今晚（5/8）回家继续蓝图入门 + 基础移动。** 不会因为"AI 一秒能做"就跳过——
- 我学的不是"怎么连这根线"
- 我学的是"为什么这根线要这么连，错了会出什么问题，AI 写错了我能不能 debug"

> **AI 让学习速度变快了，没让学习的必要性消失。**
> **会用 AI 的初学者 ≠ 会用 AI 的专业人士。** 中间隔着一整本"懂底层"。
